## 2) تعميم قاعدة التحقق — أداة `scripts/linear_verify.py` (ج15-2)

**القاعدة المعممة:** كل كتابة في Linear (تغيير حالة، تعليق، وصف، وسم) تُعاد
قراءتها حيًا وتُقارَن بالمتوقع قبل التبليغ عنها. الأداة تنفذ ذلك للعمليات
الثلاث الشائعة:

```
python3 scripts/linear_verify.py verify 3A-708 --status "In Progress" \
    --labels "Phase 2" --estimate --estimate-hours 3
python3 scripts/linear_verify.py comment 3A-708 --body "..." [--expect-marker TEXT]
python3 scripts/linear_verify.py set-status 3A-708 --state Done
```

- `verify`: يعيد قراءة البند وتعليقاته ويفحص الحالة/الأوسمة/وجود «تقدير»
  وقيمته/وجود تعليق يحمل علامة. خروج 0 = الكل ناجح، 1 = فشل.
- `comment`: ينشر ثم يعيد القراءة ويتحقق من ظهور النص.
- `set-status`: يحدّث بـ`id` (لا `issueId` أبدًا) ثم يعيد القراءة ويتحقق
  (ومع Done يتحقق من `completedAt`).
- تنبيه: `list_comments` محدودة الصفحة الأولى (50 تعليقًا)؛ إن لم توجد العلامة
  وكانت هناك صفحة تالية، تطبع الأداة INCONCLUSIVE وتخرج 1.

**اختبارات الأداة (2026-11-24):** 8 اختبارات وحدة (CLI مُحاكى) خضراء، منها
اختبار صريح أن التحديث يستخدم `id` لا `issueId`. اختبار حي: `verify` على
3A-705 ‏(6/6) وعلى 3A-708 ‏(4/4)؛ و`comment` على 3A-708 نُشر وتحقّق منه
بإعادة القراءة (تعليق `e7440725`).

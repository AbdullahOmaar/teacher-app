## 1) حذف الحساب من أوله لآخره (فجوة 32 — البند الأساسي) — ✅ منفَّذ ومختبَر طرفاً لطرف

**ما كان موجوداً:** التصدير الكامل موجود سلفاً (BackupPage: ملف JSON بـ 28 جدولاً + الإعدادات، مالك فقط) — أما حذف الحساب فلم يكن موجوداً أصلاً (صفر إشارة في `src/` و`supabase/`).

**التنفيذ:**
- **هجرة 0046:** دالة `delete_my_teacher_account()` — ‏security definer‏ بـ `search_path` مثبّت + حارس تفويض صريح (`auth.uid()` + صف مدرس للمالك) + رفض الحساب التجريبي العام في الخادم نفسه (`demo@teacher-app.com`) + تنفيذ `authenticated` فقط. معاملة ذرية واحدة: صف المدرس ← يتتابع إلى 40 جدولاً (مطابقة لقيد FK الحي) ← مستخدم Auth (يتتابع إلى الهويات والجلسات وعوامل MFA).
- **هجرة 0047 (تصحيح 0046):** اكتشف اختبار E2E الحي أن الحذف المباشر من `storage.objects` محظور بمشغّل `storage.protect_delete()` (‏42501‏ — مخرج الصيانة الوحيد هو جلسة تضبط `storage.allow_delete_query='true'`، ولا يُستخدم داخل دالة منتج). الدالة الآن **تعدّ** كائنات إثباتات المدرس وتعيدها كـ `storage_objects_orphaned` بدل حذفها.
- **العميل:** `deleteMyAccount()` (إعادة إدخال كلمة السر ← RPC ← مسح التخزين المحلي + خروج) + بطاقة `DeleteAccountCard` في الإعدادات (مالك فقط، مخفية عن الحساب التجريبي، خطوتان: تسليح ← كلمة سر + تأكيد ثانٍ، مع رابط لصفحة النسخ الاحتياطي) + 18 مفتاح i18n جديداً + 11 اختبار وحدة (تدفق + تقرير + ترجمة أخطاء).
- **الأنواع مولّدة من المخطط الحي** (`scripts/gen_db_types.py`: 42 جدولاً، 57 دالة).

**الاختبار الحي E2E** (`scripts/test_account_deletion.py` — **24/24 PASS**):
- سالب: نداء بلا جلسة مرفوض؛ نداء بجلسة الديمو مرفوض (`demo account cannot be deleted`) والمدرس التجريبي سليم.
- موجب: نداء المالك ينجح بتقرير (أعداد لكل جدول + 1 كائن يتيم).
- تحقق: صف المدرس + كل الصفوف المزروعة (طالب/مجموعة/فاتورة/دفعة/إثبات/توكن/اشتراك Push/سجل نشاط/إعدادات) + مستخدم Auth — كلها اختفت؛ المدرسان الآخران untouched؛ خط الأساس مستعاد حرفياً (2/3/42).
- صف `storage.objects` **يبقى يتيماً موثقاً** (الملف غير قابل للوصول في bucket خاص بلا أي صف يشير إليه) — السكربت ينظفه بعد الاختبار بمخرج الصيانة نفسه.

**قيد موثق (متابعة):** تنظيف دوري لأيتام `payment-proofs` (مقارنة الـ bucket بمعرّفات المدرسين الأحياء بمفتاح الخدمة أو بمخرج الجلسة) — مهمة صيانة لاحقة، لا تحجب الحذف.

## 2) تجهيز ما قبل الإطلاق: النسخ الاحتياطية + CAPTCHA — ✅ تحقق وتوثيق (بلا كود)

- **النسخ الاحتياطية:** تحقق حي (Management API): ‏`walg_enabled: true`‏، ‏`pitr_enabled: false`‏، وقائمة النسخ فارغة — **لا نسخ منصة على الطبقة المجانية** (PITR يتطلب Pro — قرار مالك). آلية النسخ الفعلية هي نسخة JSON التي ينزّلها المالك (BackupPage) وهي **غير مشفرة** — خيار التشفير بكلمة مرور استرجاع هو SEC-L4، قرار مالك معلّق سلفاً (REQUEST-OPTIMIZATION). لا كود جديد: التنفيذ قبل قرار المالك يغيّر صيغة النسخة.
- **CAPTCHA:** تحقق حي من إعدادات Auth: ‏`security_captcha_enabled = False`‏ (المزوّد hcaptcha غير مفعّل) وصفر إشارة في الكود. التفعيل يحتاج مفاتيح مزوّد (hCaptcha/Turnstile) لا يملكها المالك بعد — **خطوة مالك معلقة**: إنشاء حساب المزوّد + ضبط المفتاحين في إعدادات Auth، ثم يتحقق منها اختبار تسجيل دخول. الإجراء الدقيق موثق هنا لا منفَّذ.
- **نطاق نسخة JSON (تحقق):** ‏BACKUP_TABLES = 28 جدولاً + الإعدادات؛ المستثنى موثق في `apiBackup.ts` (الهوية، العضويات، جداول التوكنات الأربعة + روابط الحجز، الـ views الأربع). ملاحظة: صور إثباتات الدفع ليست في ملف JSON أصلاً (تعيش في Storage) — موثق سلفاً.

## 3) جولتا التشديد الأمني SEC-L7 + SEC-L8 — ✅ منفَّذتان

**SEC-L7 (مقارنة سرّ `send-push` + ‏VAPID_SUBJECT‏):**
- المقارنة ثابتة الزمن موجودة في المصدر (`secretEquals` بلا خروج مبكر) والدالة الحية **الإصدار 10** (أحدث من إصدار الإصلاح) — والبوابة متحقق منها حياً: طلب بلا سرّ = **401 `{"error":"unauthorized"}`**.
- الباقي من البند: العنوان الافتراضي `mailto:admin@example.com`. التغيير في هذا الـPR: السر أصبح إلزامياً صراحةً (فارغ افتراضياً) + تحذير في سجلات الدالة عند استخدام الاحتياطي + توثيق المتطلب في الترويسة — **بلا تغيير سلوكي** (الدفع الحي يعمل، والتحقق من وجود السر حياً غير ممكن عبر الـ API — الأسرار لا تُقرأ). **خطوة مدير معلقة:** ضبط سرّ `VAPID_SUBJECT` (بريد اتصال حقيقي) على الدالة عند إعادة نشرها عبر قناة نشر الدوال.

**SEC-L8 (‏`uri_allow_list`‏):** تحقق حي ثم تنفيذ: أُزيل `http://localhost:3000/**` من القائمة الحية (PATCH عبر Management API + إعادة قراءة للتأكيد). بقي `http://localhost:5173/**` عمداً — التطوير المحلي النشط يحتاجه (استعادة كلمة السر تعيد التوجيه إلى origin). شرط إزالته لاحقاً: توقف التطوير عن مصادقة localhost.

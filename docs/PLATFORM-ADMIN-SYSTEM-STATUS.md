# حالة النظام — قسم لوحة أدمن المنصة (3A-933)

طلب مالك 2026-11-28: الأدمن يتأكد إن الدنيا تمام من مكان واحد.
القسم داخل لوحة `/admin` نفسها وخلف بوابتها نفسها
(`RequirePlatformAdmin` + حارس `is_platform_admin` خادمياً) — لا
سطح صلاحيات جديد ولا مهاجرة جديدة. التنفيذ:
`src/features/platform-admin/SystemStatusSection.tsx` + منطق
`src/features/platform-admin/systemStatus.ts`.

## ما يعرضه القسم — ومصدر كل قيمة

| العنصر | المصدر الحي | عند الغياب |
|---|---|---|
| رابط البرودكشن | متغير البناء `VITE_PRODUCTION_URL` (نقطة الإعداد الواحدة) | حالة «لسه مش منشور» مصممة — لا رابط وهمي أبداً |
| رابط الديمو | أصل البيئة الجارية (`window.location.origin`) — البيئة الحالية اسمها الرسمي «ديمو» | — (موجود دائماً) |
| صفحة الحجز العامة | نفس الأصل + ‎`/book` | — |
| النسخة + وقت النشر | `lib/buildInfo` (`versionStampLine`) — مصدر سطر الإصدار نفسه، من `package.json` + وقت البناء المحقون | — |
| التطبيق بيرد | `GET /api/health` لحظة فتح القسم (بلا تخزين مؤقت) + زمن الرد | «لا يرد» — حالة معروضة، لا خطأ خام |
| قاعدة البيانات بترد | نداء `platform_overview` بحارس الأدمن — يمرّن PostgREST + القاعدة + RLS بجلسة الأدمن | «لا يرد» — حالة معروضة، لا خطأ خام |
| آخر نسخة ليلية ناجحة | `platform_settings` مفتاح `last_backup_at` (انظر نقطة الربط) | «لسه مش مفعّلة» مصممة + تلميح الإعداد |

لكل رابط زر نسخ: واجهة Clipboard الحديثة أولاً وبديل مصمم
(حقل مؤقت + `execCommand`) عند رفض الإذن، وتغذية راجعة «اتنسخ»
عند النجاح فقط، ورسالة نسخ يدوي عند فشل الوسيلتين. زر «إعادة
الفحص» يعيد قياس الفحصين الحيّين فوراً. لا قيمة في القسم محفوظة
أو مكتوبة يدوياً — كل شيء يُقاس/يُقرأ لحظة العرض.

## نقطة إعداد رابط البرودكشن

`VITE_PRODUCTION_URL` متغير بناء (مثل بقية `VITE_*`): يُضبط في
إعدادات مشروع Vercel الخاص ببيئة «برودكشن» عند إنشائها ضمن
إعداد الإطلاق، بقيمة رابطها الرسمي. حتى يُضبط يبقى صف البرودكشن
على حالة «لسه مش منشور». القيمة تُنقّى في `resolveProductionUrl`:
بروتوكول http(s) فقط وقصّ للمسافات والشرطة الأخيرة — أي قيمة
مشوّهة تسقط إلى حالة الغياب بدل عرض رابط مكسور.

## نقطة ربط النسخ الليلي (عقد آلية النسخ المستقبلية)

آلية النسخ الليلي تُبنى مع إعداد البرودكشن (خطة الاسترداد:
تصدير ليلي خارج Supabase + احتفاظ 14 ليلة). عند نجاح كل نسخة
تكتب الآلية — عبر service role — صفاً واحداً في جدول
`platform_settings` القائم (مهاجرة 0057، قراءة أدمن فقط بسياسة
`platform_settings_admin_select`، والكتابة service role حصراً):

- `key` = `last_backup_at` (الثابت `LAST_BACKUP_KEY` في
  `systemStatus.ts`)
- `value` = نص jsonb بلحظة النجاح بصيغة ISO 8601 UTC، مثال:
  `"2026-11-28T01:00:00.000Z"` (قيمة jsonb من نوع string)

القسم يقرأ الصف عند فتح اللوحة: قيمة صالحة تُعرض بتوقيت القاهرة
المحلي للمتصفح (`toLocaleString('ar-EG')`)، وغياب الصف أو تشوّه
القيمة يعرض «لسه مش مفعّلة» — لا لحظة مخترعة أبداً. لا مهاجرة
مطلوبة لهذا الربط: الجدول وسياسته قائمان من 0057.

## حالات مصممة فقط — لا أخطاء خام

فشل أي فحص/قراءة في هذا القسم ينتهي إلى حالة معروضة بجملة عربية
من القاموس (`platformAdmin.system*`): الفحوص لا ترمي أبداً
(مصير الـ catch معلن في `systemStatus.ts` — النتيجة نفسها هي
الحالة)، وقراءة النسخة ترمي فقط عند خطأ حقيقي غير غياب الجدول
فتعرض اللوحة سطر «تعذّر قراءة حالة النسخ» المصمم.

## 1) نظام الإصدارات الحاكم

- **كل فيز = إصدار:** فيز 1 = ‏1.0 · اكتمال فيز 2 = ‏2.0.
- **كل نشر إنتاجي بينهما +0.1** من رقم الإصدار الجاري.
- **سطر الإصدار من بيانات البناء نفسه** (`__APP_VERSION__` من
  `package.json` ‏= 1.0.0 حالياً + `__BUILD_TIME__` محقونان عند
  البناء — `lib/buildInfo.ts`) ويظهر داخل التطبيق وعلى
  السبلاش؛ كتابته يدوياً ممنوعة، وغيابه يرفض النشر (مرجع
  الاختبار §7-3).
- **الدمج ≠ النشر:** منذ تجميد 2026-11-25 مصدر الإنتاج هو فرع
  `release/phase-1` المقفل، ودمجات `main` تولّد معاينات فقط.
  قبل التجميد كان دمج `main` ينشر تلقائياً — التمييز بين
  العهدين أساسي لقراءة السجل تحت.

## 4) قاعدة التعبئة الأمامية (إلزامية من اعتماد هذا السجل)

**كل نشر إنتاجي — ويب أو دوال أو مهاجرات أو إعداد — يُلحق
قيداً بهذا السجل في لحظة النشر نفسها** بالقالب تحت. قيد ناقص
= النشر غير مكتمل، ويُبلَّغ سطر النشر الفوري للمدير (معرّف
النشر + الرابط + الوقت) قبل أي تقرير موسّع. التحقق من النشر
يكون من **جلب الـ alias الحي نفسه** (بصمة/سطر إصدار) لا من
لوحة Vercel وحدها.

```markdown
### YYYY-MM-DD HH:MM EET — <عنوان النشر> — الإصدار X.Y
- **ما نزل:** <مكوّنات الدفعة: بناء/دوال/مهاجرات/إعدادات>
- **معرّف النشر:** <deployment id / بصمة البناء>
- **الفحوص:** <CI على الـ PRs + نتائج سيناريوهات القبول الدائمة
  المنطبقة من مرجع الاختبار §5 بأرقامها>
- **المهاجرات المطبّقة بهذا النشر:** <أرقام أو «لا شيء»>
- **خط الأساس بعد النشر:** <18/18 أو الانحراف الموثّق>
- **ملحوظات/استثناءات:** <أي قرار مدير/مالك حكم هذا النشر>
```

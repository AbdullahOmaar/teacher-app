# دليل الحوادث والرجوع (Incident Runbook — §15 من المعيار، 3A-302)

المشغّل والمسؤول المناوب: مالك المشروع. لا أسرار ولا بيانات شخصية في
هذا الدليل عمداً — القيم في مديري أسرار Vercel/Supabase فقط.

## أسطح الكشف

| السطح | أين |
|---|---|
| أخطاء النشر والتشغيل | Vercel ← المشروع ← Deployments / Logs |
| قاعدة البيانات والمصادقة والدوال | Supabase ← المشروع ← Logs / Auth / Database |
| بوابات CI والأمان | GitHub ← Actions (آخر run على main) |
| توصيل الإشعارات | جدولا `push_delivery_log` و`push_digest_log` (فشل/نجاح) |
| أفعال إدارية داخل التطبيق | صفحة سجل النشاط (activity_log) |

روتين مؤقت حتى اعتماد تتبّع أخطاء آلي (فجوة R2 في جدول الامتثال):
مراجعة أسبوعية سريعة لسجلات Vercel/Supabase وفشلات push_delivery_log.

## أول استجابة

1. حدّد النطاق: انحدار نشر؟ بيانات؟ مصادقة؟ خارجي (Supabase/Vercel/Meta)؟
2. قيّم الخطورة بمقياس §14: ‏Critical (تجاوز مصادقة/تسرّب بيانات) →
   احتواء فوري قبل أي تحليل؛ High فأقل → إصلاح مجدول سريع.
3. وثّق الوقائع والزمن والقرارات في مهمة Linear الحادثة.

## الرجوع (Rollback)

- **الواجهة:** Vercel ← Deployments ← النشر السابق ← Promote to
  Production (فوري)، أو `git revert <commit>` + push إلى main.
- **قاعدة البيانات:** ممنوع تعديل هجرة مطبّقة. الإصلاح بهجرة تالية جديدة
  عبر `run_migration.py` (statement-by-statement). الاسترجاع الكامل:
  من النسخ الاحتياطي داخل التطبيق (الإعدادات ← النسخ الاحتياطي ←
  استيراد) — مساره مختبَر فعلياً (restore drill ‏GO ‏35/35 في 3A-299).
- **دوال Edge:** إعادة نشر نسخة المصدر السابقة من git عبر Management API.

## تسريب سرّ (§10: دوّر أولاً، ثم نظّف)

1. **التدوير فوراً** من مصدر السرّ: مفاتيح Supabase (لوحة المشروع)،
   مفاتيح VAPID + ‏`PUSH_INTERNAL_SECRET` + سرّ Send-SMS-Hook (أسرار
   المشروع في Supabase ثم إعادة نشر الدوال المتأثرة)، توكنات Meta عند
   تفعيلها مستقبلاً.
2. بعد التدوير: فحص Gitleaks على التاريخ كله، وتنظيف المواضع، ومراجعة
   سجلات الوصول عن فترة التعرّض.
3. إعادة كتابة التاريخ وحدها ليست إصلاحاً أبداً.

## حوادث المصادقة/الإساءة

- إيقاف التسجيلات مؤقتاً: ‏`disable_signup=true` في إعدادات Supabase Auth.
- قناة OTP واتساب: مفتاح الإيقاف `WHATSAPP_OTP_ENABLED=false` (مقفلة
  افتراضياً أصلاً) — إيقاف فوري بلا نشر.
- إبطال جلسات: Supabase Auth ← Users ← إنهاء جلسات المستخدم المتأثر.

## إيقاع تدوير الأسرار

- عند الاشتباه: فوراً كما أعلاه.
- دورياً: مراجعة الأسرار الداخلية (PUSH_INTERNAL_SECRET، سرّ الـ Hook،
  VAPID) مع المراجعة الربع سنوية للمعيار والأذونات (متابعة R9).

# استرداد كلمة السر برمز واتساب — قناة المنصة (3A-927)

> حالة البند: **في الكود فقط** — مبني بالكامل خلف أعلام مطفأة،
> التفعيل لاحقاً إعدادات وأسرار فقط بلا أي تطوير (قرار المالك
> 2026-11-27 ~23:08: واتساب جاهز في الكود بالكامل قبل تجميد فيز 2،
> والإطلاق بالإيميل؛ التفعيل بعده خطوة إعدادات).

## 1) لماذا مسار جديد (لا يوجد استرداد هاتفي أصلي)

Supabase Auth لا يملك `resetPasswordForPhone` — الاسترداد إيميل فقط
(3A-904)، وSend SMS Hook لا يصلح للاسترداد لسببين: حمولته لا تفرّق
بين دخول واسترداد، وحلّاله يرسل عبر **قناة المدرس** (0026). قرار
المدير الحاكم: الاسترداد يُرسل على **قناة المنصة** — المستخدم
المقفول بره حسابه قد لا تملك قناة مدرّسه وجوداً أو عملاً، فالكود
يخرج من رقم المنصة بأصول Meta في أسرار المشروع.

## 2) المكوّنات

| الجزء | المكان |
|---|---|
| الدالة الحدّية | `supabase/functions/send-whatsapp-recovery/` (`core.ts` نقي + `index.ts` مدخل Deno) — الدالة الثامنة |
| جدول الأكواد + دالتان داخليتان | مهاجرة `0076_whatsapp_recovery.sql` (كود فقط — تُطبَّق عند تجميد فيز 2 + بوابة QA بقاعدة التجميد) |
| عميل الويب | `requestWhatsappRecoveryCode` / `verifyWhatsappRecoveryCode` في `src/features/auth/api.ts` |
| الواجهة | `src/features/auth/WhatsappRecovery.tsx` داخل صفحة الاسترداد (تبديل قناة) |
| علم العميل | `WHATSAPP_RECOVERY_ENABLED` في `src/lib/phone.ts` من `VITE_WHATSAPP_RECOVERY_ENABLED` (افتراضي false) |

## 3) الدورة

1. المستخدم في `/reset-password` يختار «الاسترداد برمز واتساب»
   (لا يظهر إلا بعلم العميل) ويكتب رقمه → `action: 'request'`.
2. الدالة: Kill switch ← تطبيع الرقم المصري ← حدود معدل ← بحث
   الرقم بين مستخدمي Auth (`find_auth_user_id_by_phone_internal`).
   **رقم غير مربوط: رد 200 محايد بلا إرسال ولا تخزين** (منع تعداد
   الحسابات — نفس عقد حياد مسار الإيميل).
3. كود 6 أرقام يُولَّد ويُخزَّن **مجزّأً SHA-256 فقط** بصلاحية
   10 دقائق، ويُرسل بقالب مصادقة Meta من رقم المنصة (الكود في
   معامل الجسم ومعامل زر النسخ معاً — مفارقة Meta الموثّقة في
   WHATSAPP-OTP-DESIGN.md §4.3). فشل الإرسال **يبطل الكود المخزّن**
   فوراً (502) — لا كود حي بلا رسالة.
4. المستخدم يكتب الكود + كلمة سر جديدة ← `action: 'verify'` في نفس
   الطلب: مقارنة تجزئة بتوقيت ثابت، وعند التطابق تُعيَّن كلمة السر
   عبر Admin API ويُستهلك الكود. لا جلسة وسيطة ولا رابط.

## 4) الأمان (معايير البيت)

- **تجزئة فقط:** لا كود صريح في القاعدة ولا في أي سجل (الهاتف
  يُسجَّل مقنّعاً).
- **سقف محاولات:** 5 لكل كود، بعدّاد ذرّي
  (`increment_recovery_attempts_internal` — لا قراءة-ثم-كتابة).
- **حدود معدل لكل رقم:** فاصل 60 ثانية بين الطلبات + 3 أكواد/ساعة.
- **رد تحقق واحد عام** لكل فشل (خاطئ/منتهٍ/مستنفد/بلا كود) — لا
  أوراكل يفرّق بين الحالات.
- **الجدول خادمي صرف:** RLS مفعّلة بلا أي سياسة (سابقة 0024) —
  anon/authenticated ممنوعان قراءة وكتابة، والدالتان الداخليتان
  `service_role` فقط (search_path مثبّت + بوابة تنفيذ — نمط 0026).
- **لا بوابة JWT على الدالة** عند النشر (`verify_jwt=false`) —
  المستدعي مقفول بره بلا جلسة؛ البوابات هي Kill switch وحدود
  المعدل والتجزئة والسقف (نفس تعليل send-push الموثّق).
- **مصير صريح لكل خطأ:** كل فشل خادمي/مخزني يُترجم لحالة HTTP
  بمغلف `{error:{http_code,message}}`، وكل حالة تُترجم في العميل
  لرسالة عربية مصممة من القاموس — لا خطأ خاماً أبداً.

## 5) الأعلام والأسرار (أسماء فقط)

- عميل: `VITE_WHATSAPP_RECOVERY_ENABLED=true` في بناء الويب.
- خادم: `WHATSAPP_RECOVERY_ENABLED=true` (Kill switch).
- أصول المنصة: `WHATSAPP_ACCESS_TOKEN` + `WHATSAPP_PHONE_NUMBER_ID`
  (رقم المنصة) + اختيارياً `WHATSAPP_RECOVERY_TEMPLATE_NAME`
  (يرجع إلى `WHATSAPP_OTP_TEMPLATE_NAME` ثم `otp_code`).
- وضع `WHATSAPP_RECOVERY_MOCK=true` يتجاوز Graph (اختبار/طوارئ) —
  يبقى التخزين والتحقق حقيقيين.

## 6) خطوات التفعيل (عند قرار التفعيل — لا كود)

1. تطبيق مهاجرة 0076 (عند تجميد فيز 2 + بوابة QA).
2. نشر الدالة مع `verify_jwt=false`.
3. ضبط أسرار المنصة أعلاه + قلب `WHATSAPP_RECOVERY_ENABLED`.
4. بناء الويب بـ `VITE_WHATSAPP_RECOVERY_ENABLED=true` ونشره.
5. قبول حي: رقم مربوط معروف ← كود يصل ← تعيين سر ← دخول بالسر
   الجديد؛ ورقم غير مربوط ← لا رسالة ورد محايد.

## 7) حدود صادقة

- البحث بالرقم يعتمد على `auth.users.phone` (المربوط من إعدادات
  واتساب/ربط الهاتف) — حساب بلا رقم مربوط لا يصله الكود، ورده
  المحايد لا يكشف ذلك؛ الاسترداد بالإيميل يبقى متاحاً دائماً.
- قالب المصادقة نفسه المستخدم في OTP الدخول (اسماً ولغة) ما لم
  يُضبط اسم مستقل للاسترداد.
- لا تدوير تلقائياً لصفوف الأكواد القديمة — صفوف مستهلَكة/منتهية
  تبقى سجلاً أمنياً صامتاً (حجمها محدود بحدود المعدل).
